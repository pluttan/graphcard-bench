# graphcard-bench

Замер графовой СУБД Memgraph на данных LDBC FinBench против модели карты-ускорителя T4. Карта обходит рёбра графа на ПЛИС: 80 ядер, у каждого своё префиксное дерево в DDR. Карты здесь нет. Её заменяет модель T4 на C++ внутри модуля Memgraph, а время карты модуль считает по тактам симуляции RTL. Memgraph и процессор меряются по-настоящему.

Цель замера: проверить, сколько выигрыша карты останется против сильного процессора.

## Запуск в Docker

Нужен Docker на x86-64. Для замера GPU нужен ещё NVIDIA Container Toolkit, на DGX OS он стоит. Сборка берёт с Docker Hub образы `ubuntu:24.04` и `memgraph/memgraph:3.12.0`. Сервер `download.memgraph.com` бывает медленным, поэтому образ его не использует.

Соберите образ прямо из репозитория:

```sh
docker build -t graphcard-bench https://github.com/pluttan/graphcard-bench.git#main
```

Ветку `#main` пишите явно. Старый сборщик Docker без buildx иначе ищет ветку `master` и падает с ошибкой `couldn't find remote ref master`.

Перейдите в каталог для результатов и запустите замер:

```sh
docker run --rm --init --hostname "$(hostname)" -v gcb-data:/gcb/data -v "$PWD":/out graphcard-bench
```

Контейнер выполняет `make all`. Если контейнер видит GPU, он выполняет ещё `make gpu`. В текущем каталоге появятся архив `results-<машина>-sf<N>.tgz` и журнал `run-<машина>.log`. Пришлите оба файла.

Ключи `docker run`:

- `-v gcb-data:/gcb/data`: том Docker для данных FinBench, следующий запуск не качает их снова;
- `--hostname "$(hostname)"`: имя машины в названиях файлов;
- `--gpus device=3`: замер GPU на карте 3, `--gpus all` отдаёт контейнеру все карты;
- `--cpuset-cpus 0-127`: только ядра 0–127, пакет берёт число потоков по ним.

Переменные `make` пишите после имени образа: `graphcard-bench SF=10 CLIENTS=64`.

Модули Memgraph и замеры на C++ контейнер собирает при старте, с ключом `-march=native`. Поэтому один образ работает на любом процессоре x86-64.

## Запуск без Docker

Нужно:

- Ubuntu 22.04, Ubuntu 24.04 или Debian 12 на x86-64;
- `g++` с C++20, `make`, `curl`, `dpkg-deb`, `python3` не ниже 3.10;
- библиотеки из зависимостей пакета Memgraph: `libpython3`, `libseccomp2`, `libatomic1`, `libuuid1`, `libssl3`;
- место на диске: около 4 ГБ для SF1 и около 20 ГБ для SF10 (оценка);
- права root не нужны: Memgraph распаковывается в каталог репозитория.

Запустите всё одной командой:

```sh
make all            # FinBench SF1: 264 тыс. счетов, 3,4 млн рёбер
make all SF=10      # FinBench SF10, примерно в 10 раз больше
```

`make all` ставит Memgraph и venv, качает данные, собирает модули, грузит базу, прогоняет замеры, останавливает Memgraph и пакует результаты. Пришлите файл `results-<машина>-sf<N>.tgz`.

Если порт 7687 занят, задайте другой: `make all MG_PORT=7688`.

## Потоки и приоритет

Все замеры идут с `nice -n 10`, чтобы не мешать другим задачам машины. Число потоков задают `CPU_THREADS` (тест процессора и памяти), `CLIENTS` (клиенты Memgraph) и `SWEEP` (ряд клиентов для `parallel.py`). По умолчанию все три берут все логические процессоры, которые видит процесс.

## DGX A100

Машина с 8 A100, на которой пакет проверяют первой: NVIDIA DGX A100, DGX OS на Ubuntu 22.04, ядро `5.15.0-1072-nvidia`. Процессоры: 2 × AMD EPYC 7742, 128 ядер и 256 потоков, 2 узла NUMA, L3 512 МБ. Память около 2 ТБ, драйвер CUDA 12.2.

- Запускайте образ Docker. Свободную карту покажет `nvidia-smi`, её номер передайте в `--gpus device=N`.
- Машина общая. Если на ней идёт чужая работа, ограничьте ядра, например `--cpuset-cpus 0-127`.
- Если Docker недоступен вашему пользователю, запустите `make all` без Docker. Пакет Memgraph для Ubuntu 22.04 `make` выберет сам.
- Без Docker `make gpu` ставит cupy с NVRTC 12.2 под драйвер и берёт карту с наибольшей свободной памятью.

## Что меряется

Файлы лежат в `results/<машина>-sf<N>/`:

| Файл | Что внутри |
|---|---|
| `machine.txt` | процессор, память, NUMA, GPU, версия Memgraph |
| `bw.txt` | скорость чтения памяти на 1, 8, половине и всех потоках |
| `cpubench.txt` | `std::map`, упорядоченный массив и хеш-таблица на 1 млн и 16 млн ключей |
| `batch-tcr1.txt`, `batch-hubs.txt` | один запрос Memgraph: обход в ширину от счетов TCR1 и от 100 крупных счетов, Cypher и модуль на C++ |
| `parallel-hubs3.txt` | весь сервер: обход на 3 шага от 100 крупных счетов при 1, 8, 16, ... клиентах до числа ядер |
| `gpc-tcr1.txt` | модуль `gpc.khop`: каждый счёт TCR1 сверяется с Cypher, время карты по одному счёту |
| `gpc-batch.txt` | процедура `gpc.khop_batch`: пачки из 100 и 1000 крупных и 10 000 случайных счетов, Memgraph одним запросом и всеми клиентами против карты |

Каждый замер `gpc` сверяет с Cypher число счетов, которые нашёл обход от каждого стартового счёта. Если хоть один ответ разошёлся, замер останавливается.

Отдельно можно померить GPU: `make gpu` ставит cupy и гоняет сортировку, поиск и пересечение массивов. Версию пакетов CUDA `make gpu` берёт по драйверу:

- драйвер с CUDA 12.x: `make gpu` ставит ту же версию;
- драйвер с CUDA 13 и новее: `make gpu` ставит 12.9;
- драйвер с CUDA 11 и старше не подходит.

## Как читать `gpc-batch.txt`

Строка выглядит так:

```
memgraph one query 3.738 s | 24 clients 0.934 s | card 0.0517 s + host 0.1242 s = 0.1759 s | 21.2 and 5.3 times
```

- `memgraph one query`: время исполнения запроса, его сообщает сама Memgraph;
- `N clients`: та же пачка, которую делят N клиентов в отдельных процессах, время по часам;
- `card`: время карты по модели: 80 ядер, 200 МГц, задержка DDR 150 нс, PCIe 2 мкс на шаг обхода и 10 ГБ/с;
- `host`: настоящее время слияния ответов на этой машине, `THREADS` потоков;
- в конце выигрыш против одного запроса и против всех клиентов.

Сильный процессор ускоряет и Memgraph, и слияние `host`. Время `card` от процессора не зависит.

## Эталон: стенд Kraftway

Два Xeon Gold 6336Y, 48 ядер и 96 потоков, по одному каналу памяти на сокет. Машина читает память со скоростью 5,5–12 ГБ/с. FinBench SF1, `make all` 10.11.2026:

| Пачка, 4 шага | Memgraph, 1 запрос | Memgraph, 96 клиентов | Карта + слияние |
|---|---|---|---|
| 100 крупных счетов | 1,10 с | 338 мс | 43 мс |
| 1000 крупных счетов | 3,71 с | 735 мс | 146 мс |
| 10 000 случайных счетов | 2,23 с | 456 мс | 85 мс |

Весь сервер Kraftway быстрее всего обходит граф при 32 клиентах: от 29 до 53 млн рёбер в секунду. Разброс между прогонами подряд такой же большой, на хосте и в Docker. Один клиент везде даёт 2,6 млн. Модель карты обходит около 91 млн рёбер в секунду.

## Состав

| Путь | Что лежит |
|---|---|
| `Dockerfile`, `docker/run.sh` | образ на Ubuntu 24.04 с Memgraph из `memgraph/memgraph` и его старт: `make all`, `make gpu`, файлы в `/out` |
| `include/text_search_config.hpp` | заголовок Memgraph 3.12.0 под лицензией BSL, без него не собирается `mgp.hpp`, а в пакете его нет |
| `bench/mg.sh` | запуск Memgraph из пакета, который `make` распаковал в `memgraph/` |
| `bench/prep.sh`, `bench/remap.awk` | подготовка FinBench: склейка таблиц и нумерация счетов с нуля |
| `bench/load.py` | загрузка счетов, переводов и снятий в Memgraph |
| `bench/khop.cpp` | модуль Memgraph: обход в ширину на процессоре |
| `bench/gpc_khop.cpp` | модуль Memgraph `gpc`: зеркало рёбер в модели T4, обход и время карты |
| `bench/*.py` | замеры, сверка с Cypher |
| `bench/cpubench.cpp`, `bench/bw.cpp`, `bench/gpubench.py` | процессор, память и GPU без Memgraph |
| `t4/` | модель префиксного дерева T4 на C++ |

Нумерация счетов нужна из-за ошибки Memgraph 3.12: `toInteger` разбирает строку через `double`, и номера FinBench из 19 цифр склеиваются.
